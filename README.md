# RAG Basics

A hands-on, progressive walkthrough of Retrieval-Augmented Generation (RAG), built as a series of Jupyter notebooks — from a minimal retriever to an agentic RAG system with evaluation.

## Notebooks

| Notebook | Topic |
|---|---|
| [`01_rag-basics.ipynb`](01_rag-basics.ipynb) | Indexing and retrieval fundamentals: chunking, embeddings, and a Chroma vector store |
| [`02_rag_chain_ollama.ipynb`](02_rag_chain_ollama.ipynb) | A full Retrieve → Augment → Generate chain using a local `llama3.2` model via Ollama |
| [`03_pdf_lcel_prompting.ipynb`](03_pdf_lcel_prompting.ipynb) | Ingesting real PDFs and rewriting the chain with LCEL (LangChain Expression Language) plus prompt engineering |
| [`04_rag_agent.ipynb`](04_rag_agent.ipynb) | Agentic RAG: retrieval as a tool the LLM decides to call, built with LangGraph |
| [`05_rag_evaluation.ipynb`](05_rag_evaluation.ipynb) | Evaluating RAG quality: retrieval metrics (Hit Rate, etc.) and generation quality |

## Stack

- [LangChain](https://www.langchain.com/) / [LangGraph](https://www.langchain.com/langgraph) — orchestration
- [Chroma](https://www.trychroma.com/) — vector store
- [Ollama](https://ollama.com/) — local LLM inference (`llama3.2`)
- OpenAI / HuggingFace models — used in select notebooks
- [uv](https://docs.astral.sh/uv/) — dependency management

## Setup

```bash
uv sync
```

Some notebooks call the OpenAI API and will prompt for an `OPENAI_API_KEY` at runtime (via `getpass`, not stored anywhere). Others run entirely locally through [Ollama](https://ollama.com/) — install it and pull the model first:

```bash
ollama pull llama3.2
```

Then open the notebooks in order:

```bash
uv run jupyter lab
```

## Data

`data/sample.txt` is a small sample text file used by the early notebooks.

Notebook 3 onward also expects a PDF at `data/document.pdf`. It's not included in this repo — any PDF works, but to reproduce the saved outputs exactly, download the AWS [*Data Analytics Lens*](https://docs.aws.amazon.com/pdfs/wellarchitected/latest/analytics-lens/analytics-lens.pdf) whitepaper and save it as `data/document.pdf`:

```bash
curl -L -o data/document.pdf https://docs.aws.amazon.com/pdfs/wellarchitected/latest/analytics-lens/analytics-lens.pdf
```

The `chroma_db/` vector store is generated by running the notebooks and is not tracked in git.
